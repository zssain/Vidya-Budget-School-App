## Goal
Move every screen of the prototype into the structured frontend in `src/`, looking and behaving exactly the same, using safe HTML templates, event delegation and translation keys. Data still comes from an in-memory mock that copies the prototype's logic, behind the same function names the real Rust commands will have.

**Temporary exception to AGENTS.md:** business logic is allowed only inside `src/api/mock/`, because Rust does not exist yet. It is deleted piece by piece from P2.7 to P4.4. Nothing outside `src/api/mock/` may contain business rules.

## Tasks

### Task 1 — Styles
Split the prototype's `<style>` block, **without changing any values**, into:
- `src/styles/tokens.css` — the `:root` variables
- `src/styles/base.css` — reset, typography, layout (nav, top bar, view, tab bar), utility classes
- `src/styles/components.css` — buttons, inputs, cards, stats, tables, chips, pills, notes, modal, toast, attendance cards, marks inputs, receipt, report card, wizard, slips
- `src/styles/print.css` — the print rules
Import them in `main-desktop.js` in that order.
**Check:** `npm run dev` page background, fonts and a sample button match the prototype.

### Task 2 — `src/core/html.js`
Implement exactly as UI_GUIDE.md "Safe HTML":
```js
export class SafeHtml { constructor(value) { this.value = value; } toString() { return this.value; } }
export function html(strings, ...values) { /* escape each value unless SafeHtml; arrays joined; null/undefined/false → '' */ }
export function raw(value) { /* only accepts SafeHtml or string produced by html(); returns SafeHtml */ }
export function render(element, safe) { /* throws if safe is not SafeHtml; sets innerHTML */ }
export function escapeHtml(text) { /* & < > " ' */ }
```
Tests (`html.test.js`): escapes all five characters; `<script>` in a value is inert; numbers and `0` render; `null`, `undefined`, `false` render empty; arrays of `html` results render unescaped; attribute values with quotes are escaped; `render` throws on a plain string.

### Task 3 — `src/core/dom.js`
```js
export function delegate(root, handlers, { events = ['click', 'change', 'input', 'submit', 'keydown'] } = {}) { /* returns an unsubscribe function */ }
```
- Finds the closest element with `data-action` inside `root`, calls `handlers[action](event, element)`.
- For `submit`, calls `preventDefault()`.
- For `keydown`, only elements with `data-action-key="Enter"` (or the named key) trigger.
- Unknown actions log a warning in development only.
Tests: click on a child of a `data-action` element triggers; unsubscribe stops handling; input events pass the element.

### Task 4 — `src/core/format.js`
`formatRupees(n)` (Indian grouping with `₹`), `formatDate('2026-09-15')` → `15 Sep 2026`, `formatDateTime(iso)`, `formatTime(iso)` (`2:30 pm`), `timeAgo(iso, now)`. Pure functions with the current time passed in. Tests with fixed inputs, including 0, 999, 1,000, 1,00,000 and 1,23,45,678.

### Task 5 — `src/core/i18n.js` and locales
1. `t(key, params)`, `setLanguage('en'|'hi')`, `getLanguage()`, `onLanguageChange(fn)`. Missing key: return the key and warn in development.
2. Go through every visible string in the prototype and create keys in `src/locales/en.json` grouped by area (`nav.*`, `common.*`, `login.*`, `wizard.*`, `home.*`, `students.*`, `attendance.*`, `marks.*`, `fees.*`, `reports.*`, `users.*`, `activity.*`, `backup.*`, `settings.*`, `errors.*`).
3. `hi.json` must have the same keys. Use the Hindi text that exists in the prototype. For other keys, copy the English text for now (P9.1 translates).
4. Extend `scripts/check-i18n.mjs`: also scan `src/views/**/*.js` and `src/components/**/*.js` for text nodes inside `html` templates that contain two or more English words and are not wrapped in `${t(...)}`; report file and line. Allow-list: CSS class names, `data-*` values, and a `// i18n-ignore` comment on the same line.
**Check:** `node scripts/check-i18n.mjs` passes.

### Task 6 — `src/core/ui.js`
`toast(message, { kind: 'info'|'ok'|'error' })`, `openModal({ title, subtitle, body: SafeHtml, footer: SafeHtml, locked, wide, onAction })` returning `{ close, element }`, `closeModal()`, `confirmDialog({ title, message, confirmLabel, danger }) → Promise<boolean>`, `printHtml(safeHtml)`. Esc closes unlocked modals; focus moves into the modal and returns afterwards. Modal z-index above login and setup screens (the prototype had this bug; keep the fix). Tests for confirmDialog resolving true/false and locked modals ignoring Esc.

### Task 7 — `src/api/errors.js` and `src/api/commands.js`
1. `errors.js`: `class AppError extends Error { constructor({ kind, messageKey, params, message, field }) }` and `toAppError(unknown)` that turns anything thrown into an `AppError` of kind `internal` with a safe message.
2. `commands.js`: one exported async function per command in docs/API.md that the prototype's screens need (names in camelCase, parameters as documented). Each function currently calls `mock.<name>(...)` and converts thrown values with `toAppError`. Keep a `session.js` module holding the current token; functions needing a session read it there.
3. The file begins with a comment: "Every export here maps 1:1 to a Tauri command in docs/API.md. Mock implementations are temporary."
**Check:** `node scripts/check-api-drift.mjs` reports JS commands that exist in API.md and no unknown names.

### Task 8 — `src/api/mock/`
Port the prototype's data and logic into modules: `db.js` (in-memory state), `sample.js`, `setup.js`, `auth.js`, `students.js`, `attendance.js`, `marks.js`, `fees.js`, `reports.js`, `users.js`, `activity.js`, `backup.js`, `settings.js`, `index.js`. Keep the prototype's rules and messages exactly, but return the **DTO shapes named in docs/API.md** and throw `AppError`-shaped objects (`{ kind, messageKey, params, message, field }`). Keep the prototype's Web Crypto password and backup code for now.

### Task 9 — Router and app shell
1. `src/core/router.js`: `registerView(id, { title, render, navIcon, permission })`, `go(id, params)`, `rerender()`, `currentView()`. Navigation shows only views whose `permission` is in the current user's `permissions` list from `currentUser()`.
2. `src/views/shell.js`: nav, top bar (backup pill for principal, device pill otherwise, language switch), bottom tab bar with More, account modal (change password, sign out).
3. Screens before sign-in: `views/setup/welcome.js`, `views/setup/wizard.js` (7 steps), `views/setup/credentials.js`, `views/login.js`, `views/password.js` (forced and normal).

### Task 10 — Feature views
Port each screen from the prototype into its own file, same layout, same wording (through `t()`), same validation messages (shown from `AppError.message` next to `field`):
`views/home.js` (principal, accountant, teacher variants), `views/students/list.js`, `views/students/detail.js`, `views/students/form.js`, `views/attendance.js` (with monthly register print), `views/marks.js`, `views/reportcard.js`, `views/fees/register.js`, `views/fees/collect.js`, `views/fees/receipt.js`, `views/fees/daybook.js`, `views/reports.js`, `views/users.js`, `views/activity.js`, `views/backup.js`, `views/settings.js`.
Rules: views call only `commands.js`, render only with `html`/`render`, handle events only with `delegate`, and re-render after successful commands. Extract repeated markup into `src/components/` (stat card, empty state, chip bar, pill, fee pill, table, receipt copy, slip, report card).

### Task 11 — Entry points
- `main-desktop.js`: imports styles, registers every view, starts with `appStatus()` → welcome/setup, login, or home.
- `main-mobile.js`: registers only login, password, home, students, attendance, marks, reportcard, fees views. Not built yet.

### Task 12 — Tests
- At least one Vitest test per view file with `commands.js` mocked (`vi.mock`): renders without throwing, shows an error message when a command rejects with a validation `AppError`, and escapes a student named `Sierra D'Souza <b>x</b>`.
- `router.test.js`: a teacher's navigation does not include fees, reports, users, backup, settings.

### Task 13 — Parity checklist
Create `docs/PARITY.md`: a checklist of every prototype screen and action (at least 60 lines: each button, form, validation message, print action). Mark each item as ported. The developer will tick them after comparing side by side.

## Do not
- No inline event handlers anywhere (`grep -rnE "on(click|input|change|keydown)=" src` must return nothing).
- No `innerHTML` outside `core/html.js`.
- No business logic outside `src/api/mock/`.
- Do not redesign or reword anything.
