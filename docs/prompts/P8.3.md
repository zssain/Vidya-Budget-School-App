## Goal
A teacher or accountant types `sierra@vaani` and a password on the phone, the app finds the office computer, shows the matching code, waits for the principal, pins the certificate and downloads the first snapshot.

## Tasks

### Task 1 — Multicast lock
Extend the Kotlin plugin with `acquireMulticastLock()` / `releaseMulticastLock()` (WifiManager multicast lock, tag "vidya"). Rust acquires it only during mDNS discovery and releases it afterwards.

### Task 2 — Commands (mobile)
- `discover_server(school_code)`: runs `vidya-client::discover`; on success remembers address in `sync_state.server_address`; tries the remembered address first (`GET /health` with fingerprint check) before discovering.
- `remote_sign_in(username, password)`: requires `@school` in the username on first sign-in (then remembered). Flow: discover → `POST /auth/sign-in` → if waiting, return `{ status: "waiting_for_approval", matchCode }` and start polling in Rust every 2 seconds for up to 10 minutes, emitting `sync-changed` with the approval state; when approved, pin the full fingerprint in `sync_state`, store the session, cache the password hash in `auth_cache` (Argon2id of the typed password computed on the phone), run `initial_snapshot`, then return signed in.
- `MustChangePassword` path: phone shows the password change screen and calls a mobile `set_first_password` that goes to `POST /auth/first-password`.
- After pinning: any certificate mismatch → error `sync.error.not_your_school` ("This is not your school's office computer.").

### Task 3 — Screens (`src/views/mobile/`)
- Sign-in: username, password, show/hide, "Sign in".
- Looking: "Looking for your school's office computer…" with a spinner; failure screen with checks: on school Wi-Fi, office computer on with Vidya open, not a guest network; "Try again".
- Approval: large match code "482 913", text "Ask the principal to allow this phone on the office computer. The code there must match.", countdown, Cancel.
- Downloading: progress by snapshot pages.
- Errors from `AppError.message`.

### Task 4 — Tests
- Rust: sign-in state machine with a fake server client (waiting → allowed → snapshot; refused; expired; mismatch).
- Vitest: approval screen renders the code with a space; failure screen shows the checklist.
