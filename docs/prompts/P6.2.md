## Before you start (developer)
1. Create a Google Cloud project "Vidya".
2. Enable the Google Drive API.
3. Configure the OAuth consent screen (External, app name Vidya, your support email, scope `.../auth/drive.file` only). Leave it in Testing mode and add your own Google account as a test user.
4. Create OAuth credentials of type **Desktop app**. Put the client ID (and the client secret Google shows for desktop apps) in `~/code/vidya/.env.local` as `VIDYA_GOOGLE_CLIENT_ID=...` and `VIDYA_GOOGLE_CLIENT_SECRET=...`. This file is git-ignored. Never paste them into Claude Code chat.
5. Before selling, you must submit the consent screen for verification; P10.6 lists what Google asks for.

## Goal
Optional, principal-connected upload of the same encrypted backup files to a folder in the school's own Google Drive, with retention, plain-language status and restore from Drive.

## Tasks

### Task 1 — Build-time configuration
Read `VIDYA_GOOGLE_CLIENT_ID` and `VIDYA_GOOGLE_CLIENT_SECRET` at compile time (`option_env!`). If missing, the Drive section shows "Google Drive backup is not available in this build." Document in README how CI gets them from repository secrets. Note in a code comment that desktop OAuth client secrets are not confidential by Google's own documentation, and security relies on PKCE and the loopback redirect.

### Task 2 — OAuth (`crates/vidya-backup/src/drive/auth.rs`)
- Read Google's current documentation for OAuth 2.0 for desktop/installed apps; confirm the loopback IP redirect flow and PKCE; cite the page in your summary.
- Flow: bind `127.0.0.1:0` (random port); PKCE S256 verifier; random `state`; open the system browser with `tauri-plugin-opener`; accept exactly one request on the loopback server with matching `state`; show a simple "You can close this tab and return to Vidya" page; exchange code; request the user's email from the token response or userinfo only if the scope set allows it without adding scopes (if not, show "Connected" without email).
- Store the refresh token with `platform.store_secret("drive-refresh-token")`. Access tokens only in memory.
- Timeout 5 minutes; cancel button.

### Task 3 — Drive client (`drive/client.rs`) with `reqwest` (rustls)
- `ensure_folder(school_name) -> folder_id`: search for a folder the app created with name `Vidya Backups – <school name>` (with `drive.file` only files created by the app are visible); create if missing; remember id in `meta`.
- `upload(file_path) -> file_id`: resumable upload with `appProperties` `{ vidya: "1", schoolCode, kind, createdAt }`; retry with exponential backoff (1 s → 5 min, jitter) on network errors and 5xx/429; resume from the server-reported offset.
- `list_backups()`, `download(file_id, to_path)`, `delete(file_id)`.
- Retention: keep 30 daily and 12 monthly by `appProperties`; delete older ones created by the app.
- `revoke()` on disconnect, then delete the stored token.
- Verify every endpoint and parameter against Google's Drive API v3 reference; list the pages in your summary.

### Task 4 — Scheduler and status
- After each daily or manual backup, queue an upload. An upload worker runs in the background, never blocks the UI, and persists the queue in `meta` (file paths) so it continues after restart.
- Status in `backup_status`: connected email, last successful upload time, pending uploads, last error in plain words mapped from error types: no internet ("No internet since {day}. The next backup will upload when internet is back."), token revoked ("Google Drive was disconnected. Connect again."), storage full ("Google Drive is full.").
- Principal home reminder uses Drive or pen drive date (P6.1).

### Task 5 — Restore from Drive
In the restore flow add "From Google Drive": list backups for this school code, download to temp, then continue with `inspect` and `restore` from P6.1. On first run (no school), connecting Drive is allowed only inside the restore flow.

### Task 6 — Commands, screen, tests
- Commands: `drive_connect`, `drive_disconnect`, `drive_list_backups`, plus `drive_restore_download` (add to API.md).
- Tests with a local fake HTTP server (axum in dev-dependencies) implementing the used endpoints: resumable upload interrupted halfway resumes; retention deletes the right files; 401 marks disconnected; no network error message.
