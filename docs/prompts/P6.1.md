# P6.1 — Local and pen drive backups, restore

| | |
|---|---|
| Phase | 6 Backups and year end |
| Depends on | P4.4 |
| Size | large |
| Runs on | MacBook; Windows via CI and VM |
| Read first | AGENTS.md, docs/BACKUP_FORMAT.md (entire), docs/PLATFORMS.md, docs/API.md ("Backup"), prototype backup screen and `.vidyabak` v1 format |

## Goal
Encrypted backup files in the v2 format: manual save, automatic daily and monthly copies with retention, verified pen drive backups, restore with a safety copy, backup test, and import of the prototype's v1 files.

## Dependencies allowed in this prompt
`zstd`, `chacha20poly1305`, `argon2`, `sha2`, `zeroize`; for v1 import only: check whether an approved crate provides PBKDF2-SHA256 and AES-256-GCM. If none is listed, stop and ask for approval of the smallest well-maintained options (for example the RustCrypto `pbkdf2` and `aes-gcm` crates), explaining that they are only needed for importing prototype files.

## Tasks

### Task 1 — Format library (`crates/vidya-backup/src/format.rs`)
```rust
pub struct BackupHeader { .. }                          // exactly the JSON in BACKUP_FORMAT.md
pub fn write_backup(out: &Path, header: &BackupHeader, plain_sqlite: &Path, key: &Zeroizing<[u8;32]>) -> Result<u64, BackupError>;
pub fn read_header(path: &Path) -> Result<BackupHeader, BackupError>;
pub fn decrypt_to(path: &Path, key_or_password: KeySource, out_plain_sqlite: &Path) -> Result<BackupHeader, BackupError>;
pub fn derive_key(password: &str, salt: &[u8], params: &KdfParams) -> Zeroizing<[u8;32]>;
```
Errors: `WrongPasswordOrDamaged` (AEAD failure — one message for both, "The backup password is wrong or the file is damaged."), `NotABackup`, `NewerVersion`, `Io`.
Streaming is not required; files are small.

### Task 2 — Making a consistent plain copy
- Find out (with evidence from SQLCipher documentation) the supported way to produce a **plaintext** copy of an encrypted database: `ATTACH DATABASE '<tmp>' AS plaintext KEY ''` + `SELECT sqlcipher_export('plaintext')` is the documented SQLCipher approach; confirm it works with the bundled version and write a test.
- Temporary file in a private temp folder inside the data directory (`data/tmp`, created `0700`), deleted after use in all code paths (use a guard type with `Drop`).
- `PRAGMA integrity_check` on the copy must return `ok`.

### Task 3 — BackupService (`services/backup.rs`, desktop only)
| Method | Rules |
|---|---|
| `status(actor)` | backup.manage: last backup time and kind, last pen drive, last Drive (P6.2), auto enabled, next scheduled, days since last off-computer backup, list of local files |
| `save_manual(actor, password, path)` | Verify password against `backupCheck`; plain copy → write v2 file to `path`; verify by decrypting header and checking size; `meta.last_backup_at`; `backups_log`; change log event |
| `enable_auto(actor, password)` | Verify; derive key with a fresh salt; store key + salt through `platform.store_secret("backup-key")`; setting on |
| `run_auto(kind)` | Internal. Uses stored key. Writes to `backups_dir`; applies retention (BACKUP_FORMAT.md); logs |
| `list_removable(actor)` | From `platform.removable_drives()` |
| `save_to_pendrive(actor, drive_id)` | Writes into `<drive>/Vidya Backups/`, flushes, then reads it back and fully decrypts to a temp file and runs `integrity_check`; deletes the temp file; returns "safe to remove" state |
| `change_password(actor, current, new)` | Updates `backupCheck` and the stored auto key; old files still need old password (message says so) |
| `test_latest(actor)` | Decrypt newest local backup to temp, integrity check, compare row counts with header counts, delete temp, log `verify` |
| `inspect(path, password)` | Allowed with backup.manage, or with no school (restore on first run). Returns school name and code, created date, app and schema version, counts. Stores decrypted temp file under a preview id (30 minutes) |
| `restore(preview_id)` | School code must match the license's school code. Schema newer → refuse. Safety backup of current data first (if a school exists). Create a new encrypted database from the plain copy with the current key (`ATTACH ... KEY` + `sqlcipher_export`), run migrations on it, swap files atomically (rename current to `vidya.db.before-restore`, rename new into place), mark all devices `needs_resync = 1`, change log event, then ask the app to restart |

### Task 4 — Platform: removable drives
- macOS: volumes under `/Volumes` that are removable or ejectable (use the approved crates or DiskArbitration through IOKit/CoreFoundation bindings; verify; at minimum exclude the boot volume and network volumes).
- Windows: drive letters whose drive type is removable, plus USB-attached fixed drives if detectable; show label and free space.
- Windows test in CI for listing (may return empty); VM check with a USB drive passed through.

### Task 5 — Scheduler (`src-tauri/src/background/backup.rs`)
- On start and every 15 minutes: if auto is on and no daily backup today and local time ≥ 18:00, run `run_auto(daily)`; on app close request, if no daily backup today, run it before exit (with a small "Saving today's backup…" window state, max 30 seconds).
- First backup of a month also counts as monthly.
- Before migrations of a new app version and before restore: `safety` backup (hook into start sequence: if `user_version` < newest migration and a school exists, back up first using the stored auto key; if no auto key, block the upgrade with a screen asking for the backup password).
- Home reminder (principal) when last off-computer backup (pen drive or Drive) is older than 7 days.

### Task 6 — v1 prototype import
`import_v1(path, password)` in first-run restore: decrypt with PBKDF2-SHA256 (iterations from file) + AES-256-GCM, parse the prototype JSON, create a school through the same internal functions as setup (school code must match the license), give all staff new temporary passwords (`must_change = 1`) and show slips; principal must set a new password. Tests with a `.vidyabak` generated by `reference/VidyaSchoolApp_step1.html` (the developer creates one with password `backup123` and puts it in `crates/vidya-backup/tests/fixtures/`).

### Task 7 — Screens and commands
Commands from API.md "Backup" (except Drive ones). Backup screen: status cards, Save backup file, Save to pen drive (drive picker, progress, "Safe to remove"), Automatic backups toggle with password, Test your backup, Restore (file picker → password → preview → confirm with typed school code → restart). First-run Activation screen shows "Restore from a backup file". Locked "other computer" screen enables "Save a backup file" (needs backup password).

### Task 8 — Tests
- Round trip: every table identical (compare `SELECT *` ordered by primary key for all tables).
- Wrong password and one flipped byte → the same `WrongPasswordOrDamaged` error; no partial restore.
- Different school code refused.
- Retention keeps exactly 30 daily and 12 monthly with generated dates.
- Temp plaintext files are gone after success and after failure.
- Restore made on Windows (CI artifact from a test) opens on macOS test and vice versa: generate a backup in the Windows CI job, upload as artifact, and add a macOS job step that downloads and restores it (and the reverse).
- Matrix case; remove `backup.manage` from NOT_YET_IMPLEMENTED.
